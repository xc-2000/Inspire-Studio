# 微信支付充值

已接入微信支付 API v3 **Native 扫码支付（普通商户、公钥模式）**。
用户在「积分 → 购买积分」选择套餐，使用微信扫描二维码。服务端验证支付通知后，
在数据库事务内更新订单、积分余额和 `wechat_pay` 积分明细。
原有卡密兑换、外部店铺继续可用。管理员可在「系统管理 → 支付订单」分页查询订单。

## 商户配置

收款开关在 **系统管理 → 微信支付 → 微信收款**，仅管理员可修改。
修改后保存到数据库并立即用于新订单校验，无需重启；重启后仍保留设置。
关闭仅停止新下单，不影响旧订单回调验签、后台对账及积分到账。
`WECHAT_PAY_ENABLED` 仅在后台从未保存开关时作为初始值；后台保存后以数据库为准。
开启但未配置有效套餐/商户参数时，界面显示缺失项，用户端仍不可购买。

### 界面管理套餐

进入 **系统管理 → 微信支付 → 充值套餐**，点击“新增套餐”或“编辑”。
填写名称、价格（元，最多两位小数）、到账积分与排序，选择上架状态后保存。
新套餐默认下架；上架后在收款开关开启且商户配置完整时可购买。
可直接上下架，列表支持分页；最多 20 档，排序值越小越靠前。
保存即生效，无需重启；已有订单保留原金额与积分。并发编辑冲突会提示刷新，不静默覆盖。
后台从未保存过套餐时兼容 `.env` 的 `WECHAT_PAY_PACKAGES_JSON`，第一次保存后以数据库为准。
下架全部套餐时不会重新启用旧环境变量中的套餐。

先为商户开通 Native 支付，确认 AppID 已与商户号绑定。
在项目本地 `.env` 填写以下变量，私钥和 API v3 密钥不要提交 Git：

| 变量 | 内容 |
| --- | --- |
| `WECHAT_PAY_ENABLED` | 配置完成后设 `true`；默认 `false` |
| `WECHAT_PAY_APP_ID` | 商户绑定的 AppID |
| `WECHAT_PAY_MERCHANT_ID` | 微信支付商户号 |
| `WECHAT_PAY_MERCHANT_SERIAL_NUMBER` | **商户 API 证书**序列号 |
| `WECHAT_PAY_PRIVATE_KEY_PATH` | 容器内商户私钥路径，默认 `/app/payment-keys/apiclient_key.pem` |
| `WECHAT_PAY_PUBLIC_KEY_ID` | 微信支付公钥 ID，以 `PUB_KEY_ID_` 开头 |
| `WECHAT_PAY_PUBLIC_KEY_PATH` | 容器内微信支付公钥路径，默认 `/app/payment-keys/wechatpay_public_key.pem` |
| `WECHAT_PAY_API_V3_KEY` | 商户平台配置的 32 字节 API v3 密钥 |
| `WECHAT_PAY_NOTIFY_URL` | `https://你的公网域名/api/v1/payment/wechat/notify` |
| `WECHAT_PAY_PACKAGES_JSON` | 套餐 JSON 数组，默认 `[]`，未配置时不开放购买 |

把商户私钥与微信支付公钥放入 `server/config/payment-keys/`，Compose 已只读挂载，
该目录的密钥文件已被 Git 忽略。必须使用微信支付平台公钥，不能填商户证书公钥。
如果商户尚使用平台证书模式，请在商户平台按官方指引获取支付公钥及公钥 ID。
本地直跑 Java 时将两个路径改为本机绝对路径。

兼容已有导出配置中“平台证书序列号 + 对应 RSA 公钥”的固定验签方式：
`WECHAT_PAY_PUBLIC_KEY_ID` 也可填写 40 位十六进制平台证书序列号。
该方式固定信任导入的验签公钥，不自动下载或轮换平台证书；平台密钥轮换时须同步更新公钥与标识并重启。
不要把商户私钥对应的公钥当作微信验签公钥。
旧系统的 `/api/v1/payment/webhook/wxpay` 回调路径也受支持，走相同验签及到账流程。

套餐示例**仅说明格式，不是已上架售价**（金额单位为分，积分为正整数）：

```dotenv
WECHAT_PAY_PACKAGES_JSON='[{"id":"example","name":"示例套餐","amountFen":100,"credits":10}]'
```

套餐正式价格由运营确认。修改 `.env` 后重建服务端容器即可生效；已创建订单保留原价格和积分数。

```powershell
docker compose -f docker-compose-local.yml -p novanova-studio up -d --no-deps --force-recreate server
```

回调必须公网 HTTPS 可达，`127.0.0.1` 无法接收微信通知。反向代理需保留微信签名头和原始请求体。
没有商户配置时页面显示“微信支付暂未开放”，不会生成测试收款码或虚假付款记录。

## 处理规则

- 金额及积分由服务端套餐决定，客户端只提交套餐 ID 和请求 UUID。
- 相同用户及请求 UUID 仅创建一个订单，每用户每小时最多 20 个新订单。
- 使用官方 `wechatpay-java` SDK，验证接口响应、回调签名并解密通知。
- 回调校验商户、AppID、币种、订单号、金额和流水；数据库行锁及唯一微信流水防止重复到账。
- 二维码有效期 30 分钟；服务端查询确认未付款后向微信关单，不能仅凭本地超时判定支付失败。
- 浏览器每 5 秒查询；服务端对账至少间隔 10 秒，另有每分钟后台对账，关闭浏览器不影响到账。
- 回调处理失败返回 HTTP 500，允许微信重试；积分更新和订单状态同事务回滚。
- 新功能仅包含充值和订单查询，退款需通过商户平台人工处理并核对积分，未提供自动退款入口。

## 上线验收

填写真实参数、套餐和公网回调地址后，用商户允许的小额真实订单检查扫码、回调、订单及积分明细。
同一通知重复投递应只有一次充值；金额不符或签名无效不得到账。
本地自动测试使用模拟交易/临时数据库，不代表已通过真实商户支付验收。
